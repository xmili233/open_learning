# K12 教学画板：从学生场景出发的产品定义

> 状态：已确认并同步至 `MVP_PROPOSAL.md` 与 Skill
> 目标：Codex Voice 能在真实讲解过程中，逐步操控一块可读、可验证、可打断，而且不会替学生完成思考的共享教学画板。

本文只回答“学生坐在电脑前会经历什么”，不讨论实现。术语沿用 `MVP_PROPOSAL.md` 的对象模型与 `board open / patch / read`。

## 0. 结论先行

1. 主设计对象是初中数学（7–9 年级）、入口是“作业卡在一道题上”。其余年龄段和入口只作检验，不作设计驱动。
2. “不替学生思考”落成一条硬规则和一个提示梯度：**学生自己的题，永远不在画板上出现完整解答**；完整过程只出现在相似题上。
3. 画板是“共同注视的那个点”，不是第二条信息流。每一轮语音不超过两句就必须停下来提问或等待；画板一次只改一个认知动作，同时可见对象不超过 6 个。
4. “可验证”拆成两件事：内容可验证（公式、数值由本机渲染/计算）和回答可验证（学生的数值或表达式由本机判定，不由语音猜）。
5. “可打断”定义为：学生一开口或一点画板，语音停、待执行 patch 作废、画板停在当前焦点，Codex 读回状态后只提交最小修正；学生写下的东西从不被 AI 删除。
6. 由此反推，MVP 对象模型新增 `problem` 类型和 `owner` 字段，patch 新增 `mark`、`reveal`、`collapse`；`check` 是 `question` 对象的数据，不是单独动作。

## 1. 主设计对象

### 1.1 人

初二学生，晚上 8 点，数学作业第 5 题卡住 10 分钟。特征：

- 会读题，但不知道从哪里下手；
- 对“被讲一遍”有抵触，对“被问一个能答上的问题”有反应；
- 注意力单次维持约 20–40 秒，读屏速度慢于听；
- 最想要的是“把这题做完”，最需要的是“下次同类题不卡”。

### 1.2 场合

入口是“作业卡住”。选它的原因：最高频、最真实、也最容易诱使 AI 直接代做，是对“不替学生思考”最严的检验。

四种入口对“讲明白了”的定义不同，用来检验设计而不是驱动设计：

| 入口 | 学生要的 | 画板重心 | 结束条件 |
| --- | --- | --- | --- |
| 作业卡住 | 这题做出来 | 学生的题 + 一道相似题 | 学生自己写出下一步并做完 |
| 老师讲过没听懂 | 那个“为什么” | 一个可以被拆开看的对象 | 学生能用自己的话复述 |
| 考前补概念 | 一组容易混的东西分清 | 对比布局 | 学生能把新例子归类 |
| 家长辅导不了 | 有人陪着做 | 更少的对象、更慢的节奏 | 家长能看懂过程 |

## 2. “不替学生思考”的画板规则

### 2.1 硬规则

- 学生的题（`problem` 对象）的正文由学生提供，AI 只能在上面做标记（`mark`），不能改写、不能补写解答。
- 学生题的解答步骤只能由学生产出。AI 最多揭示**一步**，且只在学生尝试过并卡住之后。
- 完整过程只允许出现在 `example` 对象（相似题）上。相似题数字不同、结构相同。
- 学生写的任何对象（`owner: student`）AI 不能删、不能改，只能标记和引用。

### 2.2 提示梯度

每次学生卡住，Skill 只上升一级，不跳级。

| 级别 | 画板动作 | 语音 |
| --- | --- | --- |
| L0 定位 | 无 | “你算到哪一步了？” |
| L1 指向 | `mark` 题目中的一个条件或数量 | “这三个数之间是什么关系？” |
| L2 结构 | `put step` 写下学生刚说出的关系（内容来自学生） | “A 车 t 小时走了多远？” |
| L3 相似题 | `put example` + 逐步 `reveal` | 每步一句 |
| L4 一步 | 在学生题上 `put step`（仅一步） | “照这个，你的下一行是什么？” |
| 禁止 | 学生题的完整解答 | — |

### 2.3 学生直接要答案时

不说教、不拒绝。画板立刻放相似题完整过程（L3），语音逐步引用，最后焦点回到学生的题：“照这个，你的第一行是什么？”学生完成后再问一个迁移问题。给答案的需求被转化成“看一遍再自己做一遍”，而不是被驳回。

## 3. 可读、可验证、可打断的具体时刻

### 3.1 可读

对一个初二学生，可读就是“一眼看出现在讲到哪”：

- 同时只有一个 `focus`；焦点对象高亮，其余降级。
- 同屏对象不超过 6 个；超出时 Skill 必须先 `remove` 或 `collapse` 完成使命的对象。
- 对象正文不超过两行或一个公式；讲解文字走语音，不进画板。
- 步骤有序号，当前步骤有标记；学生随时知道“做到第几步”。
- 布局稳定：新增对象不移动已有对象。

### 3.2 可验证

两层，不能混：

内容可验证。公式由 KaTeX 渲染；数值计算由 renderer 完成并标 `verified`；AI 自己写出来的数字不带 `verified`。

回答可验证。`question` 对象可携带 `check`（期望值与类型：`numeric` / `expression` / `choice`）。学生在画板输入后，本机判定并回读事件，Codex 收到的是“对/错/等价”，不是靠听。表达式等价在 MVP 用固定样本代入比较，不引入 CAS。

解释性回答（“为什么”“用自己的话说”）仍由语音判断；画板只负责能机械判定的部分。

### 3.3 可打断

打断信号：学生开口，或点击/书写画板任意位置。点击对象同时构成 `selection`。

打断那一秒：

1. 语音停止（Codex 自身能力）。
2. CLI 不再应用尚未执行的 patch；当前 `LessonTurn` 标记 cancelled。
3. 画板停在当前 focus，不回滚、不清屏。
4. Codex `read`：版本、selection、最近学生事件。
5. 只提交与新问题相关的最小 `mark` / `focus` / `put`。
6. 学生已写的对象一律保留。

学生的体验是“我一说话它就停，我指哪它就看哪”，不是“它讲完这段再理我”。

## 4. 语音与画板的分工

画板是两个人一起看的那个点，不是并行字幕。

画板动的时候：一个新对象出现、一个状态改变、一处对比、一个标记。

画板不动的时候：鼓励、复述学生说的话、问“你觉得呢”、等待、解释因果。这些全走语音。

节奏规则：语音每说两句必须以问题或等待结束。K12 学生的注意力窗口决定了这条规则，不是风格偏好。

一轮的标准形状：

```text
patch 一个动作 → 语音引用它（≤ 2 句）→ 提问 → 等待学生 → 读回 → 下一轮
```

## 5. 会毁掉体验的失败方式

| 失败 | 表现 | 设计 |
| --- | --- | --- |
| 过早说懂 | “懂了懂了” | 口头确认不推进；必须做一步或答一道迁移题 |
| 只要答案 | “直接告诉我” | 2.3 的转化路径 |
| 走神/沉默 | 15 秒无回应 | 语音一个小问题；画板 `focus` 不变；不继续讲 |
| 幻灯片化 | 连续 put 不等待 | Skill 禁止连续两次 put 之间没有等待或问题 |
| 语音过长 | 一段讲 30 秒 | 两句规则 |
| 画面堆乱 | 对象越来越多 | 6 个上限；每个 checkpoint 清理脚手架 |
| 粗暴纠错 | “不对，应该是…” | 画板显示学生答案代入后的后果，让学生自己看到矛盾 |
| 覆盖学生 | AI 改了学生写的式子 | owner 规则 |

## 6. 端到端脚本

### 6.1 主脚本：七年级相遇问题，作业卡住

题：甲乙两地相距 240 km，A 车 60 km/h，B 车 40 km/h，同时出发相向而行，几小时相遇？

**T0**
学生读题。Codex `put problem`（owner student，正文为题目）。
语音：“你算到哪一步了？”等待。

**T1**
学生：“不知道怎么列式。”（L0 → L1）
patch：`mark` 题中 240、60、40。
语音：“两辆车相遇时，加起来走了多少？”等待。

**T2**
学生：“240。”（L2）
patch：`put step s1 "两车路程之和 = 240"`，focus s1。
语音：“A 车开了 t 小时，走了多远？”等待。

**T3**
学生：“60t。”
patch：`put step s2 "A：60t"`。
语音：“B 车呢？”学生：“40t。”patch：`put step s3 "B：40t"`。

**T4**
patch：`put question q1`，check 类型 expression，期望 `60t+40t=240`。focus q1。
语音：“三样东西都在板上了，你来写那个等式。”等待。
学生输入 `60t + 40t = 240`。本机判定等价，回读 correct。
语音：“对。剩下的解方程你自己来，算完念给我。”画板不显示解的过程。

**T5**
学生：“2.4。”
patch：`put question q2` check numeric 2.4 → correct（或直接由语音记录，因为学生口头作答）。
语音：“对。换一下：如果两车从同一地同向出发，A 追 B，等式哪里会变？”
patch：`put example e1`（同向追及题，数字相同），focus e1。等待。

学生答“变成相减”即结束；答不出则从 L1 重新开始，这次在 e1 上。

整个过程中学生题的解方程步骤从未出现在画板上。

### 6.2 分支：同一题，学生要答案

**T1'**
学生：“直接告诉我答案。”
patch：`put example e0`（相距 300，50 和 25 km/h），四个 step 逐步 `reveal`。
语音每揭示一步说一句：“先写两车路程之和……A 走的……B 走的……合起来。”
patch：focus 回 problem。
语音：“照这个，你的第一行是什么？”等待。
之后回到 6.1 的 T2。

### 6.3 检验：九年级“为什么顶点横坐标是 −b/2a”，老师讲过没听懂

不从公式开始。
patch：`put concept f1`，正文为公式 `y = x² − 4x + 3`；再 `put step` 两个对称点 (1,0) 和 (3,0)。
语音：“这两个 y 一样的点，它们中间是多少？”学生：“2。”
patch：`put step "对称轴 x = 2"`，`mark` f1 中的 −4。
语音：“2 和 −4 有什么关系？”学生：“−4 除以 −2。”
patch：更新 concept 为 `x = −b/2a`，focus。
语音：“换个 b，你猜顶点跑到哪？”patch 更新 concept，等待。
P1 阶段再评估可拖参数的 `plot`。MVP 用公式正文 + step 已能完成这次理解循环。

### 6.4 检验：八年级全等判定 SSS/SAS/ASA 混淆，考前补

patch：`compare` 布局，三个 `concept`，每个只有名字和一个图示描述。
语音：“这三个的共同点是什么？”学生：“都要三个条件。”
patch：`put example`，一个已知两边一角的图。
语音：“这个角夹在两边中间吗？”学生判断。
patch：`put question` choice 三选一。本机判定。
错了不说“错”，patch `mark` 那个角的位置，语音：“再看角在哪。”

### 6.5 边界检验：五年级“为什么除以分数等于乘倒数”，家长辅导不了

对象更少、节奏更慢、不出符号推导。
patch：`put example "6 块蛋糕，每人 1/2 块，够几个人？"`。
语音：“你先猜。”学生：“12。”
patch：`put step "6 ÷ 1/2 = 12"`，`put step "6 × 2 = 12"`，focus 两者。
语音：“两个算式一样吗？为什么一个 1/2 变成了 2？”等待。
不再往下推一般规律；家长在旁边能看懂全部过程。

## 7. 从脚本反推

### 7.1 对象模型需要补

| 补充 | 原因 |
| --- | --- |
| `problem` 类型 | 学生的题需要“AI 只读、可标记”的特殊对象 |
| `owner: student \| ai` | 学生写的东西不可被 AI 删改 |
| `question.check` | 数值/表达式/选择的本机判定 |

### 7.2 patch 动作需要补

| 动作 | 用途 | 脚本出现 |
| --- | --- | --- |
| `mark` | 在 problem 或公式正文中高亮一段 | T1、6.3、6.4 |
| `reveal` | 逐步揭示 example 的 step | 6.2 |
| `collapse` | 收起完成使命的对象，不删除 | 5 中的清理 |

保留 `put_node / remove_node / focus / clear`；不再保留边与布局操作。`check` 是 `question` 对象的数据，不是 patch 动作。

### 7.3 Skill 需要补的规则

- 学生的题永不出现完整解答；完整过程只在 example 上。
- 提示梯度 L0→L4 逐级上升，不跳级。
- 语音每两句必须以问题或等待结束。
- 连续两次 put 之间必须有等待或学生回应。
- 口头“懂了”不算；推进前必须有一步动手或一道迁移题。
- 打断后只读回状态并提交最小 patch，不清屏、不回滚。
- 纠错优先展示后果，不直接宣布对错。
- 同屏对象 ≤ 6。

### 7.4 对现有文档的修订建议

- `MVP_PROPOSAL.md` 4.3：对象模型增加 `problem` 和 `owner`；公式是正文能力，不增加独立对象类型。
- `MVP_PROPOSAL.md` 4.4：patch 增加 `mark`、`reveal`、`collapse`，question 可携带 `check`。
- `MVP_PROPOSAL.md` 3.3：并入 7.3 的规则。
- `MVP_PROPOSAL.md` 8.1：主指标增加“学生题的解答步骤中由学生产出的比例”，这是“不替学生思考”的直接度量。
- `ai_tutor_teaching_interfaces.md` P0：`check` 的本机判定（数值 + 随机代入的表达式等价）提前到 P0，因为主脚本 T4 依赖它。

## 8. 已确认的 MVP 边界

1. `problem` 只接收 Codex 从学生口述或粘贴内容中得到的文字；MVP 不做拍照识别。
2. 6 个可见对象上限由状态层强制执行；两句规则写入 Skill，pilot 后再评估是否放开。
3. 打断事件包含作答、对象选择和点击画板空白处；语音停止仍由 Codex Voice 自身负责。
